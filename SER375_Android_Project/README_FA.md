# پروژه اولیه اندروید SER-375 (نسخه 0.1.0)

این یک **پروژه منبع اولیه** برای بازکردن در Android Studio است؛ APK آماده نصب نیست.

## قابلیت‌های نمونه
- ثبت RUN، شیفت، عمق ابتدا/انتها، BIT، Casing، CR، RQD و زمان ۲۴ ساعته
- ذخیره محلی در SQLite و کار بدون اینترنت
- پیشنهاد شماره RUN بعدی و انتقال DEPTH TO به DEPTH FROM بعدی
- فایل اکسل اصلی SER-375 در assets قرار داده شده است
- تلاش برای خروجی XLSX با حفظ برگه الگو

## محدودیت‌های مهم این نسخه
- خروجی Excel فعلاً اطلاعات را در بخش «APP RUN REGISTER» زیر قالب قرار می‌دهد؛ هنوز نگاشت دقیق داده‌ها به خانه‌های اصلی گزارش شرکت تکمیل/اعتبارسنجی نشده است.
- داده‌های روز و شب فعلاً در یک فهرست ذخیره می‌شوند؛ کنترل پیوستگی عمق بین روز/شب و ریست شماره RUN طبق روال دقیق سایت باید آزمایش شود.
- مقداردهی قطرها در UI طبق اعداد اعلام‌شده کاربر است؛ این اطلاعات هنوز در خانه‌های اصلی فایل Excel نگاشت نشده‌اند.
- ساخت APK به Android Studio و دانلود وابستگی‌های Gradle نیاز دارد.

## ساخت APK
1. Android Studio را نصب کنید.
2. پوشه `SER375_Android_Project` را با گزینه Open باز کنید.
3. اجازه دهید Gradle وابستگی‌ها را دریافت کند.
4. از مسیر Build > Build APK(s) استفاده کنید.

فایل قالب در `app/src/main/assets/SER-375_Template.xlsx` است.


## اصلاحات نگاشت اکسل در این مرحله
- خروجی از ردیف‌های ورودی قالب اصلی استفاده می‌کند: روز 8 تا 18، شب 20 تا 28.
- داده‌های تاریخ‌دار در برگه‌ای با نام همان تاریخ نوشته می‌شوند.
- ستون‌های اصلی A، B، D تا J و N تا V نگاشت شده‌اند.
- قطرهای P و Q بر اساس مقادیر اعلام‌شده کاربر نوشته می‌شوند.
- این تغییرات هنوز روی دستگاه اندرویدی ساخته/کامپایل و با Excel واقعی آزمایش نشده‌اند؛ APK ارائه‌شده نیست.
- محدودیت ظرفیت قالب: حداکثر 11 ران روز و 9 ران شب در هر برگه روزانه. اگر عملیات بیش از این باشد باید ردیف‌های قالب به شکل کنترل‌شده افزوده شوند.


## ادامه کار: محاسبات ردیف‌های گزارش
در نسخه سورس v3، هنگام خروجی‌گیری فرمول‌های ستون‌های زیر برای هر ران درج می‌شوند:
- K (L cm): اختلاف DEPTH TO و DEPTH FROM ضرب‌در 100
- L (T m در عنوان قالب): زمان سپری‌شده بر حسب دقیقه از START تا FINISH
- M (L/T): مقدار K تقسیم بر L، در صورت غیرصفر بودن زمان

این فرمول‌ها از روی عنوان ستون‌ها و فرمول کمکی موجود در قالب بازسازی شده‌اند و باید با نمونه‌های واقعی شرکت مقایسه شوند؛ به‌خصوص معنی دقیق ستون L در فایل اصلی باید از مسئول گزارش تأیید شود.

## ساخت APK در Android Studio
1. نصب Android Studio و JDK سازگار با نسخه Android Gradle Plugin.
2. بازکردن پوشه پروژه.
3. اجرای Gradle Sync با اینترنت برای دریافت وابستگی‌ها.
4. Build > Build APK(s).
5. نصب APK روی گوشی آزمایشی و آزمایش چند گزارش روز/شب.


## نسخه v4: خروجی قابل دسترس
در Android 10 و جدیدتر، فایل XLSX پس از خروجی‌گیری در پوشه Downloads ذخیره می‌شود تا کاربر بتواند آن را با Excel یا از طریق پیام‌رسان ارسال کند. هنوز APK ساخته نشده است.


## نسخه v5: کنترل ورودی‌ها
- بررسی قالب تاریخ به صورت `yyyy.MM.dd`
- بررسی قالب ساعت ۲۴ ساعته و محدوده ساعت/دقیقه
- بررسی اینکه CR و RQD در بازه ۰ تا ۱۰۰ باشند
- محاسبه RUN بعدی و DEPTH FROM اولیه فقط با رکوردهای همان تاریخ جاری انجام می‌شود

توجه: تاریخ نمونه در برنامه از تاریخ میلادی دستگاه ساخته می‌شود؛ برای استفاده عملی در تقویم شمسی باید انتخابگر تاریخ شمسی اضافه شود. در این نسخه کاربر می‌تواند تاریخ شمسی را دستی وارد کند.


## نسخه v6: مسیر ساخت APK از طریق GitHub Actions
یک workflow در `.github/workflows/build-apk.yml` اضافه شده است تا بعد از بارگذاری پروژه در مخزن GitHub و اجرای Actions، APK آزمایشی ساخته و به‌صورت artifact قابل دریافت شود.

مراحل:
1. یک repository جدید در GitHub بسازید.
2. محتویات این پوشه را بارگذاری کنید.
3. در زبانه Actions، اجرای `Build SER-375 Android APK` را انتخاب کنید.
4. پس از موفقیت build، artifact با نام `SER375-debug-apk` را دانلود کنید.

این روش نیاز به ابزار Android SDK روی کامپیوتر شخصی را برای build ابری کم می‌کند، اما نیاز به حساب GitHub و دسترسی اینترنت دارد. این workflow هنوز اجرا نشده و موفقیت build تضمین‌شده نیست؛ هر خطای build باید از log برطرف شود. APK ساخته‌شده debug است، نه نسخه امضاشده برای انتشار.
